# Устройство Linux-порта

Linux-версия использует общее ядро RuTool: чтение и проверку `.rut`, установку,
резервные копии, восстановление, сеть и QML-интерфейс. Системные операции
реализованы отдельно и выбираются CMake при сборке.

Основа — RuTool 2.1.1, коммит `5c11513`. Часть Linux-кода, тестов и упаковки
перенесена из RuTool-Linux, коммит `96776dc`, с адаптацией к этому дереву.
Исходные лицензии и уведомления сохранены.

## Системные реализации

Все пути в этом документе указаны относительно `client-v2`.

| Файл в `src/platform/linux/` | Назначение |
| --- | --- |
| `FileOps.cpp`, `Posix.hpp` | Открытие файлов, блокировки, проверка места и процесса игры, замена файлов и сохранение на диск |
| `LocalData.cpp` | Защита локальных данных AES-GCM, хранение ключа, идентификатор установки |
| `RuntimeLite.cpp` | Определение каталога приложения |
| `GameDiscovery.cpp` | Поиск игры в библиотеках Steam и каталогах Proton |
| `Main.cpp` | Запуск Linux-приложения, версия и проверка интерфейса без сети |
| `ClientUpdates.cpp` | Сообщение о ручном обновлении AppImage |

Windows launcher, DLL payload и updater собираются только на Windows.
Linux использует собственные файлы запуска и обновления. При изменениях
общего запуска приложения эти реализации нужно согласовывать между собой.

`cmake/Linux.cmake` подключает публичную конфигурацию, ресурсы и Linux-тесты.
Скрипты упаковки и `packaging/linux/` формируют AppImage с Qt и плагинами.

## Изменения общего кода

На Linux регистр символов в путях учитывается. Политика задана в
`include/rutool/platform/Runtime.hpp` и применяется к установке, ключам
резервных копий и очистке загрузок. Сравнение расширений файлов и идентификаторов
не менялось. Выбранная папка игры приводится к реальному пути, чтобы алиасы
Steam не создавали разные записи для одной установки.

В `src/app/ClientController.cpp` и `ClientOperations.cpp` добавлена проверка
режима `--smoke-test`: в нём не запускаются рабочие операции и обновление
содержимого с сервера. Сам режим реализован в Linux `Main.cpp`.

В `src/network/ServiceClient.cpp` добавлен Linux User-Agent с версией приложения.
В `qml/InstallerWindow.qml` показана кнопка ручного обновления Linux и скрыта
кнопка Windows-обновления.

В `third_party/zlib-1.3.2/` добавлен отсутствовавший обязательный заголовок
`zconf.h`. В `crypto/CMakeLists.txt` приватный тест добавляется только при
наличии его исходника; публичные Linux-тесты от него не зависят.

## Замена файлов и восстановление

В `src/core/Installation.cpp` откат учитывает каждую попытку замены файла.
Это нужно потому, что `renameat` уже мог заменить файл, а следующий `fsync`
завершиться ошибкой.

При ошибке проверяется текущее содержимое цели:

- Исходный хеш: дополнительная замена не нужна.
- Хеш перевода: выполняется откат из резервной копии.
- Неизвестный хеш или ошибка чтения: автоматический откат останавливается,
  журнал и резервные копии сохраняются.

Поправка отката действует на обе ОС. Windows после общих изменений пока
не проверена; сохранение Windows-исходников само по себе не доказывает совместимость.

Ключ локальных данных записывается с `fsync` и повторно открывается для чтения
до использования. Повреждённый или недоступный существующий ключ не заменяется
новым автоматически. Без ключа существующий журнал расшифровать нельзя.

Часть общего установщика по-прежнему использует Qt I/O. Полной защиты от
одновременной подмены каталогов нет. Права на рабочие каталоги и ограничения
файловых блокировок описаны в [инструкции](../BUILDING-LINUX.md).

## Сопровождение

Следующий релиз оригинала вливается в Linux-ветку с сохранением общей Git-истории.
Особого внимания требуют изменения установки, журналов, платформенных интерфейсов,
форматов пакетов, подписей и серверного API. Слияние без конфликтов ещё не
подтверждает работоспособность.

Перед выпуском запускаются CTest, отдельная сборка без тестов и проверки AppImage.
При изменениях транзакций повторяются сценарии ошибок и восстановления.
Результаты текущей версии: [LINUX-VALIDATION.md](LINUX-VALIDATION.md).
