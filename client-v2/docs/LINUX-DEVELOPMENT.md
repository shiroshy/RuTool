# Подготовка Linux-выпуска

Linux-ветка развивается самостоятельно, сохраняя общую историю с оригиналом.
Общее ядро отвечает за пакеты, подписи, установку и восстановление.
Системные операции и обновление приложения реализованы отдельно для Linux.
Переписывание клиента с нуля и поддержка Windows-сборки этой ветки в план не входят.

## Что готово

Есть нативный Qt/QML-клиент, поиск игры через Steam/Proton, загрузка перевода,
установка, резервные копии и восстановление после прерывания операции.
AppImage собирается для x86_64 с минимальной glibc 2.35.

Обновлятор проверяет подписанный канал, размер и хеш AppImage, сохраняет
предыдущую версию и перезапускает клиент. Поддерживаются промежуточные выпуски
для смены ключа или протокола. Настоящий канал пока не настроен.

Ревью изменений файловых транзакций, восстановления и обновлятора завершено.
Исправления включены в сборку от 26 ноября; автоматические проверки прошли.
Это не заменяет перечисленные ниже проверки на реальных системах.

## До публичного выпуска

1. Подготовить ключ подписи и канал обновлений в `shiroshy/RuTool`.
   Первый публичный AppImage уже должен уметь обновляться.
2. Проверить настоящий переход между опубликованными AppImage:
   замену, запуск новой версии, промежуточный выпуск и ручной возврат к предыдущей.
3. На релизном кандидате повторить загрузку перевода, установку, запуск игры
   и восстановление. Проверить обнаружение игры и её процесса через Proton.
4. Проверить обычный запуск AppImage и запуск без FUSE, Wayland/X11,
   масштабирование интерфейса и Steam Deck. Deck входит в первый выпуск.
5. Проверить настоящий Premium и платные дополнения при наличии кодов доступа.
   Без этих проверок нельзя заявлять их работоспособность.
6. Собрать финальный AppImage с рабочим каналом, проверить состав,
   подготовить контрольные суммы, описание выпуска и известные ограничения.

Результаты и оставшиеся пробелы перечислены в [состоянии проверок](LINUX-VALIDATION.md).

## Совместимость и сопровождение

Форматы `.rut`, журналов, ключей и резервных копий сохраняются.
Изменение формата требует миграции; удаление старых данных её не заменяет.
Проверки подписей, хешей и Premium сохраняются при любых изменениях порта.

Обновления оригинала переносятся обычным слиянием выбранного commit или tag.
Перед слиянием локальные изменения должны быть сохранены. Установка,
криптография, API и платформенные интерфейсы требуют проверки поведения,
даже если Git не сообщил о конфликтах.

Старые ветки канала и переходные выпуски остаются доступными для обновления
старых клиентов. Закрытый ключ хранится отдельно от исходников и AppImage.
Потеря или компрометация ключа требует отдельного плана перехода.

## Необязательные улучшения

Дополнительная защита обновлятора: приватный каталог подготовки с правами
`0700` и временные файлы `0600` с момента создания. Сейчас общий загрузчик
создаёт временные файлы с учётом umask. При групповой записи и доступе другого
локального пользователя остаётся возможность изменения файла между проверкой
и запуском; поздний chmod не отзывает уже открытые дескрипторы.
Сценарий выявлен статически, эксплуатация не воспроизводилась.
Это улучшение не является условием завершения текущего плана.

Автоматический возврат к предыдущей версии при сбое нового GUI также
не реализован. Предыдущий AppImage сохраняется для ручного запуска.
